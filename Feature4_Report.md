Feature 4: SMT Interference and Shared Core Resources

This experiment investigates the performance trade-offs of Simultaneous Multithreading (SMT), specifically focusing on resource contention between sibling threads. While SMT allows a single physical core to present multiple logical processors to the OS to hide memory latency, these logical processors must share critical hardware resources, including execution units (ALUs), L1/L2 caches, and the memory controller interface. To quantify the impact of this sharing, I designed a controlled experiment on Ubuntu 22.04 under WSL2 (reporting 20 logical CPUs). I compared two distinct micro-benchmarks—a compute-bound integer loop and a memory-bound array traversal—under two conditions: running in isolation (alone) versus running concurrently with a competing thread pinned to the sibling logical CPU (interf).

The results for the compute-bound workload demonstrate the efficiency of modern superscalar architectures. As illustrated in the compute interference boxplot, the execution time distributions for the isolated and interference cases are statistically indistinguishable. Both configurations settled around a median execution time of 0.320 seconds, yielding a slowdown factor of 1.00. This suggests that the integer arithmetic workload did not saturate the available execution ports or that the processor's instruction scheduler successfully interleaved instructions from both threads without stalling, allowing the core to maintain near-peak throughput.

In stark contrast, the memory-bound workload exposed the limitations of shared hardware resources. When two memory-intensive threads competed for the same physical core's cache hierarchy and load/store buffers, performance degraded significantly. The median execution time rose from approximately 0.85 seconds in the baseline case to over 1.20 seconds under interference, corresponding to a slowdown factor of 1.42. The clear separation between the two boxplots confirms that memory bandwidth and cache capacity are "zero-sum" resources; unlike ALU cycles, which can be time-multiplexed effectively, cache contention manifests as immediate increases in effective memory access latency.

These findings highlight that SMT is not a universal performance booster but a workload-dependent feature. While it offers excellent throughput gains for compute-bound or mixed workloads that leave execution units idle, it introduces substantial "noisy neighbor" penalties for memory-bound applications. This dictates that high-performance schedulers must be SMT-aware, specifically avoiding the co-scheduling of memory-intensive threads on the same physical core to preserve memory bandwidth and minimize cache pollution.

Although the experiment was conducted under WSL2, the observed interference patterns are rooted in physical core resource sharing rather than OS-level scheduling artifacts. Since SMT sibling threads ultimately contend for the same execution and memory structures, the relative slowdown trends remain representative of native hardware behavior.
