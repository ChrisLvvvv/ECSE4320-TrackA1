Feature 1: CPU Affinity

This experiment investigates the impact of explicit thread pinning on execution stability and cache locality. Thread migration across cores is essential for load balancing, but it can introduce performance penalties due to cache invalidation and context switching overhead. To quantify these effects, I developed a custom C micro-benchmark compiled with -O2 optimization running on Ubuntu 22.04 under WSL2. The benchmark targets two distinct system behaviors: a compute-bound phase that saturates the ALU with integer arithmetic, and a memory-bound phase that repeatedly traverses a large array to provoke cache contention. I compared the standard Linux CFS scheduling against a pinned configuration using taskset to bind the process to a single logical core, conducting eight iterations per configuration to capture run-to-run variability.

The results indicate that CPU affinity primarily influences stability rather than raw throughput in this environment. For the compute-bound phase, the mean execution time remained constant at approximately 0.27 seconds regardless of pinning. The memory-bound phase showed a similar pattern with an average time of 0.36 seconds with a standard deviation on the order of 0.02 seconds across runs; however, the pinned configuration demonstrated marginally lower standard deviation compared to the unpinned runs. This suggests that while explicit pinning did not unlock significant speedups, it successfully reduced jitter by mitigating cold-start effects associated with core migration.

The limited performance gain can be attributed to two factors. First, the Linux scheduler’s "soft affinity" heuristic naturally attempts to keep processes on the same core to preserve cache warmth, making explicit pinning redundant for simple, single-threaded workloads on an idle system. More importantly, the virtualization layer of WSL2 fundamentally alters the experiment's premise. Since taskset only pins the thread to a virtual CPU (vCPU), the underlying Windows host scheduler remains free to migrate that vCPU across physical cores. Consequently, strictly enforcing physical L1/L2 locality is impossible in this environment. While pinning improved consistency at the guest OS level, true hardware isolation would require a bare-metal environment to bypass the hypervisor’s scheduling abstraction.
