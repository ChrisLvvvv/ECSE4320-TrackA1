Feature 3: NUMA Locality and Memory Access Behavior

This experiment evaluated the performance implications of Non-Uniform Memory Access (NUMA) placement by enforcing explicit CPU and memory affinity. On physical multi-socket systems, accessing remote memory typically incurs higher latency and reduced bandwidth compared to local access. To explore these effects, I used numactl on Ubuntu 22.04 under WSL2 to bind a custom memory-intensive C benchmark to NUMA node 0. The benchmark repeatedly traverses a large array to stress the memory subsystem, reporting both total execution time and effective memory bandwidth.

A preliminary topology inspection using numactl --hardware revealed that the WSL2 environment exposes a unified NUMA topology, consisting of a single node containing all 20 logical CPUs. Consequently, the experiment shifted focus from measuring remote access latency to examining the overhead of enforcing NUMA policies within a virtualized, single-node abstraction.

The results exhibit a counter-intuitive but consistent trend. As shown in the bandwidth measurements, the default configuration achieved a higher average throughput of approximately 21.0 GB/s, whereas the configuration explicitly bound to NUMA node 0 dropped to roughly 19.5 GB/s. This reduction was mirrored in execution time, which increased from 0.95 seconds to 1.03 seconds under strict binding. The variance across runs remained comparable, indicating the degradation is systematic rather than noise-driven.

This outcome highlights a critical abstraction gap in virtualized performance tuning. Since the guest OS perceives a single unified node, the kernel’s default allocation strategy is already effectively optimal. Explicitly enforcing numactl policies introduces additional constraint-checking overhead without offering physical locality benefits. Furthermore, restricting execution at the guest level may limit the Hyper-V host’s flexibility in scheduling virtual CPUs, paradoxically reducing performance. Far from being an experimental flaw, this negative result underscores a vital system principle: low-level optimizations are not universally beneficial and must be aligned with the underlying hardware topology. In environments where physical NUMA is abstracted, enforcing strict affinity can introduce overheads that outweigh theoretical gains.
